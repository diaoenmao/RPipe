# 研究工作要求

## 一、适用范围与入口

本地权威文本现已随Git提供：[研究计划规范中文正本](<../research/standards/研究计划规范 Research Plan Standard.md>)、[研究计划模板中文正本](<../research/standards/研究计划模板 Research Plan Template.md>)，以及[规范英译](../research/standards/research_plan_standard_en.md)、[模板英译](../research/standards/research_plan_template_en.md)。两份中文均为DEM交付的2026-10-16更新原字节；来源、SHA-256及DEM内部缺失依赖见[正本入口](../research/standards/README.md)。英文供理解，中文优先；本页保留RPipe宏观方案/Study分工适配，不要求新增重复计划或改变运行布局。

本文件按 DreamSoul 的研究计划规范、模板及 knowledge 中的相关 skills 适配 RPipe：先从灵感与文献形成研究问题，再联合规划文献调研、数据、模型、算法、指标和实验设计，以证据回答问题。它规定研究工作的最低说明要求，不新增库接口、目录层级或执行命令。

- **开始前：** 写清为什么做、怎样比较、怎样判断、需要什么资源。六个方面都要回应，不适用时说明原因和替代证据，未知信息保留“待确认”。
- **执行时：** 先完成小规模检查与必要基线，正式实验按已确认计划和授权执行；计划状态与实际运行状态分别记录。
- **结束后：** 保留实际条件、原始结果、失败和负结果，说明证据支持、反驳或尚不足以判断什么，以及结论边界。

适用于方法、复现、数据与 Benchmark、系统与应用研究，也适用于文献和理论工作。纯文献研究用证据比较与缺口分析回应验证；理论研究用证明、反例、误差界或复杂度分析回应，不为了填满模板强行训练或跑矩阵。

| 可独立验收的具体实验 | `studies/<name>/docs/PLAN.md`；引用实际存在的宏观方案，提取本轮问题、条件、预算和判据 |

研究要求与具体课题方案分开维护：本文件不是 RPipe 的研究计划，也不声称本仓库已存在宏观 `docs/research/`。缺少宏观资料时先补充真实问题与依据，不编造来源。本仓库的历史 Study 是模板验证实例，不是下游项目的研究结论。

源规范建议使用单份 `docs/research-plan.md`，同时允许沿用项目结构；这里采用 RPipe 已有的“宏观方案 → 具体 Study”分工，不再新建同内容的平行计划。Study 的执行模板只是起点，以下研究说明须按问题补齐，不能用 YAML 或调度安排代替研究设计。目录和执行细节见[根 README 的 Study 指南](../../README.md#study-使用指南)与 [Studies 入口](../../studies/README.md#从宏观研究提取具体-study)。

## 三、从灵感到可执行计划

1. **记录灵感。** 注明异常观察、实践困难或想法的来源与触发条件，提出用于检索的初步问题；新颖性和可行性在核验前保持待验证。
2. **核查文献。** 围绕问题检索、筛选、阅读与比较，寻找候选路线、强基线、反例和缺口，说明继续、调整或搁置的依据。
3. **明确问题与假设。** 写清对象、条件、最接近工作、预期机制与范围，给出能够支持或反驳判断的观察。探索性工作可先列问题，后续独立检验与发现过程分开。
4. **联合制定六方面方案。** 核对下表各项是否共同回答同一个问题，再把可独立验收的一部分提取为 Study。模型、数据和算法的变化分别记录，不把多项变化归因于单一方法。
5. **小规模检查与基线。** 核对样本、输入输出、测量协议、来源、数值及失败边界；基线异常先解释差异。代码能运行、数值一致与研究假设得到支持是不同结论。
6. **按计划执行与分析。** 正式规模、预算、判据和授权确认后再扩大；重要变更记录日期、原因及影响，区分预设分析、探索性分析和事后修改。
7. **形成结论与新问题。** 回答原问题，说明支持、反驳和证据不足的部分，保留边界、负结果及下一步的来源。

## 四、六个方面的最低说明

| **方面** | **计划中需要说明的内容** |
| --- | --- |
| 文献调研 | 问题与检索范围、关键词、信息截止日与实际检索日期、纳入和排除依据；核心来源的版本、章节或图表定位、实际阅读范围、路线与基线选择依据 |
| 数据 | 来源、许可或授权、版本、样本单位、规模与分布、标注误差、清洗和预处理；划分及隔离单位、重复与泄漏检查、已知偏差和不可公开制品的获取或核验方式 |
| 模型 | 输入输出、结构或数学定义、参数与状态、假设与边界、初始化或权重来源及版本；简单基线与最接近方法，固定与变化部分 |
| 算法 | 关键步骤、公式或伪代码，相对基线的改动与机制假设；目标函数、超参数、调参方式、随机性、状态更新、停止与失败条件、计算代价、复用实现及 commit |
| 指标 | 主指标与必要质量、资源或风险约束；定义、单位、方向、测量对象、聚合方式、实现版本、阈值依据及统计方案；尚未确定的值不写成已确认判据 |
| 实验设计 | 每个实验对应的问题或假设、处理因素、对照、控制条件、评价数据、重复方案、成本与判读规则；小规模进入正式实验的条件、调参与最终测试分工、效度限制和停止规则 |

核心文献的证据表应同时提取问题、数据与模型、算法、指标与实验条件，以及结论、局限和本课题用途。区分作者主张、自己的判断和本地复现数字；条件不同的跨论文数字不能直接排名。引用量和发表场所只是发现线索，未检索到工作不等于证明研究空白。

数据划分须匹配泛化问题，避免测试信息进入训练、预处理估计、模型选择或校准。既有 Benchmark 优先沿用明确协议，修改时说明可比性。涉及敏感数据时记录适用的授权、隐私与使用限制，不将私有数据或凭据提交到 Git。

实验按问题选择基线复现、主对照、消融、稳健性、边界或失败分析，不强制跑满所有组合。“同预算比质量”和“同质量比成本”分别定义。随机实验按预期效应、方差和预算制定重复方案，不统一要求固定次数；统计分析使用实际独立单位，不能把相关样本当独立重复，也不能用一次最好结果证明稳定性。需要置信区间、显著性检验或多次比较处理时，事先说明方法与假设，并判断实际意义；相关性不直接写成因果结论。

DOE、运筹学、贝叶斯优化和贝叶斯实验设计按问题选用，不是必选工具。使用时记录相应因素与水平、决策变量、目标或效用、约束、搜索空间、预算和停止规则。自适应搜索保留完整试验轨迹及公平比较口径，选定方案须独立评价或进入预定验证阶段，搜索最优值不直接当最终证据；复用现有配置与日志，不为这些方法另建研究框架。

## 五、执行与证据要求

### （一）运行前

- PLAN 明确本轮对照、固定条件、seed、实际计算精度、预算、指标、质量门、失败处置和停止条件；缺失关键来源或判据时，不将计划标记为具备正式实验条件。
- 计算精度包含实际 TF32 / 混合精度等设置。严格数值对照须保持一致，seed 与确定性开关不能替代精度约定。
- 并行先校准目标设备的显存、主存、线程、I/O 和整体吞吐，系数可调整，不规定统一比例。避免多个进程写同一 Run；性能测量记录负载、并发、预热、同步与计时边界，不混入竞争任务。测试并行约定见 [testing.md](testing.md)。
- 按已有结构核对源码与数据来源、实际项目入口和 provenance / freeze；环境元数据不能替代源码核验。具体合同见 [flow.md](../code/flow.md) 与 [structure.md](../code/structure.md)，不虚构命令或参数。

### （二）运行与结论

每次正式运行记录 Run ID、代码 commit 及实际未提交差异、配置、数据与划分、模型版本、依赖、硬件、随机与精度设置、实际命令、预算、状态、原始结果与制品位置。独立复跑使用新 `version` / Run 身份；恢复沿用相应合同，不能把旧成功结果计入当前验收。

报告分别说明执行状态、流程验收和研究质量，区分计划数字、实测结果、推断与未验证事项。保存波动、失败、负结果、协议变更及重复运行反例，不通过挑选成功结果、放宽门限或删除证据获得通过。`NUMBERS.md` 与自动聚合只提供数字，不能代替人工分析；现有忽略的原始产物不会随 clone 提供，须标明保存位置与复现所需条件。

实现与实验任务应关联计划中的问题和验证，PR 给出真实条件、结果与限制。分支、评审和可选 Actions 见 [cicd.md](cicd.md)：关闭 Actions 不免除必要验证，未执行不记为通过。本规范不自动授权大规模实验、提交、推送、发布或修改云端资料。
