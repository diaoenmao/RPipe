# RPipe v0.4.0 发布报告

发布日期：2026-10-15（Asia/Shanghai）。上一正式版本为 [v0.3.1](v0.3.1.md)，提交 `7a15c46b75c5eb951cccd60ed7b9fc3463db90f5`。目录与版本材料经 [PR #57](https://github.com/DreamSoul-AI/RPipe/pull/57) 进入 dev；按 Enmao 本次明确授权，发布经 dev → main 普通 merge、实际 main 验收、annotated tag `v0.4.0` 与 GitHub Release 完成。实际发布提交、PR 与 CI 在 Release 正文附录记录，不把工作分支提交当作最终标签来源。

## 一、摘要

### （一）本版内容

1. **共享输入：** 项目根 `shared/data/`、`shared/model/` 默认供 studies 下各 Study 复用不可变输入。沿用现有 dev 位置，本轮不再移动目录；Run 的模型对象、checkpoint、sampler、RNG 和可变状态独立。
2. **目录合同：** [layout.md](../code/layout.md) 列明项目顶层和 Study 级目录的位置、内容、写入方，路径改变必须先改文档，再改实现与回归；测试实际调用默认路径入口与文档对照。
3. **三类正确性收敛：** 可整体替换文本统一原子发布、status / logs 统一私有安全读取、失败保全决策等价提炼。文件架构、产物布局和 result.json 的位置、格式、含义保持不变。
4. **版本一致：** pyproject.toml、rpipe.__version__ 与 README 的版本为 0.4.0。版本号不是来源证明；下游仍须记录确切提交与本地差异。

## 二、从 0.3.x 迁移到 0.4.0

### （一）先保全来源和在跑任务

1. 核对工作区、正在运行的 Study、旧源码副本与 ORIGIN；保留 Run、checkpoint、配置、报告、provenance 和失败证据。不要覆盖运行中的下游 vendor 或实验工作树。
2. 对比目标 v0.4.0 的确切提交和下游本地改动，再更新自己的 src/rpipe。发布前使用候选提交仅作开发验证，不宣称已有正式标签；发布后按 [README 的固定版本接入](../../README.md#在其他项目中使用-rpipe) 核对标签 SHA。
3. 复制源码并不自动安装依赖；按目标 pyproject.toml 核对隔离环境和实际导入路径。无需更名项目包、搬模块或改已有 result/config 格式。

### （二）默认输入根和需要迁移的旧位置

| **资产** | **0.4.0 默认位置** | **旧缓存处理** |
| --- | --- | --- |
| 公共原始数据 / 版本化派生输入 | `<project>/shared/data/` | 旧 `<study>/shared/data/` 的相同字节输入可显式迁移 |
| 固定预训练权重 / tokenizer | `<project>/shared/model/` | 旧 `<study>/shared/model/` 的相同字节输入可显式迁移 |
| Study profile 统计 | `<study>/shared/data/<dataset>/stats.yaml` | 保持私有；迁移命令跳过 stats.yaml |
| 训练状态、checkpoint、日志和 tracker | `<study>/runs/<id>/assets/` | 不进入 shared；不因升级搬动或覆写 |

规范 Study 根为 `<project>/studies/<study>/`。非 studies 布局保留 `<study-parent>/shared` 的兼容默认；显式 shared.root 相对 Study 解析。dev 已经使用项目根共享输入的项目不需再搬一次；0.4.0 只是将其纳入正式版本迁移合同。

### （三）rpipe shared --migrate 的实际用法

以下命令在项目根、可导入目标 src/rpipe 的隔离环境执行；`studies/my_study` 换成实际 Study。

```bash
# 只显示 root/data/model 路径，不迁移、不准备数据
rpipe shared studies/my_study
# 等价的 Python 模块入口
python -m rpipe shared studies/my_study

# 仅在确认输入可共享、旧路径与公共根同卷后显式执行
rpipe shared studies/my_study --migrate
# 等价入口
python -m rpipe shared studies/my_study --migrate
```

1. 先检查 study.yaml 的 shared 设置和命令显示的目标位置。确认下载 / builder 没有其他写入者，共享输入可按格式、revision 和版本兼容；不要为绕过冲突把不同字节覆盖成同名资源。
2. `--migrate` 获取现有输入锁，先核对全部重名文件的 SHA256 与卷，再建立同卷硬链接；输出 old / shared / sha256 / same_file。旧路径保留为同一文件引用，相同字节不保留第二份磁盘副本，不改写 Run、result、provenance。
3. 不同字节冲突、嵌套根、跨卷或旧源为符号链接会拒绝；CLI 输出原始错误并退出 2。stats.yaml 与 .rpipe.lock 不作为迁移文件。已有显式引用须单独核对，不把引用迁移当复制操作。
4. 发生运行中 I/O 失败时保留输出和当前文件状态，核对哪些链接已建立后再处理；“重名冲突在链接前拒绝”不等于全批 I/O 事务回滚。不删原目录、旧失败或诊断 staging 来换取成功。
5. 跨卷时选择在同卷的显式 shared.root 或经确认的输入引用方案；命令不自动复制大文件或删除旧数据。迁移涉及硬链接，共享文件随后原地修改会影响所有引用，必须按不可变输入管理；资源内容升级使用新 revision / 目录。
6. 新源码会触发来源冻结检查。迁移后若需独立实测，先按计划建立新 Study / 隔离副本和新 version，再 fresh make、小范围正确性验证；不要重签已完成 Run 的旧 provenance，不把旧成功冒充新来源验收。

### （四）Study 私有输入设置

默认可省略整个 shared 块；以下显式写法与规范布局相同：

```yaml
shared:
  root: ../../shared
  data: project
  model: project
```

只有真实不兼容依据时，在 Study 的 PLAN 说明格式、统计口径、模型 revision 或隔离理由，再按类别选择私有输入：

```yaml
shared:
  data: study      # <study>/shared/data
  model: project   # 仍复用 <project>/shared/model
```

需要私有模型时使用 `shared.model: study`；两类可独立选择。私有例外仍只保存输入，不能把 Run 模型对象、sampler、RNG 或 checkpoint 混入其中。profile 的统计即使在默认共享 data 模式下仍为 Study 私有，显式 config.stats_path 保持优先；仅搬解析路径不向实验 config 注入绝对目录，实际输入 / 统计改变仍按研究计划重新验证。

## 三、正确性修复与兼容

### （一）三类统一规则

| **类别** | **改前风险** | **0.4.0 行为及边界** | **集成依据** |
| --- | --- | --- | --- |
| 原子发布 | 某些替换文本绕过统一 helper，index 编码失败可能截断旧证据；并发临时名与长名风险 | 可整体替换文本复用 atomic_write_text → atomic_replace，短 UUID staging、失败只清理自己的临时文件；保留 LF / mode。Logger 追加、tracker、checkpoint 和锁维持特殊协议 | [PR #46](https://github.com/DreamSoul-AI/RPipe/pull/46)、[PR #52](https://github.com/DreamSoul-AI/RPipe/pull/52) |
| 只读读取 | stat / read / decode 容错分散，坏指标或模式值可影响其他格 | status / logs 使用现有文件内的私有三态读取；计划 config 优先并校验 id / seed，缺配置保留历史 fallback；坏文件隔离，意外编程错误不静默吞掉 | [PR #49](https://github.com/DreamSoul-AI/RPipe/pull/49)、[PR #51](https://github.com/DreamSoul-AI/RPipe/pull/51)、[PR #54](https://github.com/DreamSoul-AI/RPipe/pull/54) |
| 失败保全 | 冻结拒绝可能覆盖旧成功；判断分散 | 保留 dev 已有边界，仅将 process 或初始/prepare 的 ProvenanceChangedError 决策收成私有函数。普通执行失败仍写 failed，不扩大成“任何失败保留成功” | [PR #39](https://github.com/DreamSoul-AI/RPipe/pull/39)、[PR #46](https://github.com/DreamSoul-AI/RPipe/pull/46)、[PR #55](https://github.com/DreamSoul-AI/RPipe/pull/55) |

result.json 仍是该 Run 的结果摘要，不改为指针或账本，不增加 attempts / generation 目录。旧 Run / process / tracker 的有效格式继续读取；来源冻结和严格结果校验不因兼容而关闭。本版不为历史自定义采样器承诺精确断点恢复，需按对应 Study 合同处理。
