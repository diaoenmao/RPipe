记录日期：2026-10-15（Asia/Shanghai）。本报告整理 v0.4.0 之后已合 dev 的正确性工作，并作为 v0.4.1 的发布正文。Enmao 已明确授权本次普通 merge 发布、annotated tag、GitHub Release 和五项 Issue 的发布后关闭；实际发布提交与验收以 Release 附录为准。上一正式版本为 [v0.4.0](v0.4.0.md)，main / tag 对应 `54f8d31c0f5505742677dd2ce6dec323ee114c61`；修复内容的初始代码基线为 dev `e39f7f82c3d07fa600b62727fee17587d65338c6`。正式发布须另验最终工作提交、实际 dev、dev → main 发布 PR 与实际 main；不以历史 dev 验证代替。

## 一、摘要

1. **失败写入留证：** Logger / AlgorithmTracker 的追加文件初始化不再截断检查后到达的旧字节；补齐既有失败保全与失败结果提交再失败的合同，不扩大旧成功的保留范围。
2. **安全只读展示：** status / report 的有限数与坏指标容器统一按格处理；compare 保持严格读取，对坏文件、非法参数与输出拒绝返回既有错误语义，不降级为 status 占位。
3. **原子写与并发：** Study 中可整体替换的文本复用现有原子入口；短随机 staging 只有排他创建成功后才归当前写者，失败不覆盖、移动或删除 peer。
4. **不变的磁盘合同：** 项目根 `shared/{data,model}` 继续供各 Study 共用不可变输入；Run 可变状态独立。[layout.md](../code/layout.md) 仍是唯一目录依据。模块、目录、result/config/tracker 格式与含义均不迁移。

## 三、三类统一合同与兼容边界

### （一）失败写入留证

[PR #64](https://github.com/DreamSoul-AI/RPipe/pull/64) 补六阶段原异常与失败结果编码/提交再失败的 12 项合同，验证原异常身份、日志、旧 result / peer 保全和本写者清理；既有 Runner / schedule 决策无需生产改动。PR #71 只消除追加文件初始化的截断窗口。

保留 dev 已有规则：process 拒绝，以及初始/prepare 的来源冻结拒绝保留旧成功；普通执行失败仍写 failed。Tracker.begin_run 按 checkpoint offset 恢复前缀的既有职责继续有效，不能把“留证”理解成禁止所有有意恢复操作。result.json 仍是 Run 结果摘要，不改成指针或追加账本，不新增 attempts 目录。

### （二）只读展示与严格比较

status / logs 的既有安全读取层与计划 config 优先视图保留；本次 PR #63 只统一有限数显示和坏容器隔离。缺失/读不了的单格不遮蔽正常 peer，不以容错显示代表科学门通过。

compare 是严格验证入口，不采用 status 的占位政策：相等为退出 0，不相等或必需项缺失为退出 1，已识别的文件/参数/输出 I/O 错误为退出 2。真实 checkpoint 解析异常在加载边界归为文件错误并保留 cause；意外程序异常仍传播。有效 comparison JSON 格式不变，输出失败保留原 comparison。

### （三）原子发布与专用协议

可整体替换文本使用现有 atomic_write_text → atomic_replace；取得 staging 所有权前不写、不清，失败只清当前写者创建的临时文件。PR #61 的 Study 发布合同与 PR #69 的根入口合同共同覆盖调用方，不复制局部补丁。

日志追加、Tracker JSONL / offset、checkpoint `.writing` / `.incomplete` 诊断恢复、锁 inode、固定 Git blob、校验后发布的二进制 partial 与派生图片维持专用协议；不批量清理历史诊断文件，也不把单文件原子替换当多文件事务。没有新增框架、锁层、模块搬迁或磁盘布局。

## 四、从 v0.4.0 更新的步骤

1. 保留工作区、下游源码差异、Run / checkpoint / provenance 和失败记录；不要覆盖正在运行的 vendor / 实验。核对最终发布提交与 annotated tag 的确切指向，修复内容的初始 dev 基线不等于新标签。
2. 文件、配置、缓存布局和 schema **无需迁移**。已使用项目根 shared 的项目无需再次运行迁移；`rpipe shared --migrate` 仍仅用于原有 Study 私有旧路径的显式迁移，不能因本补丁版自动执行。0.3.x 直接升级者另按 [v0.4.0 迁移指南](v0.4.0.md#二从-03x-迁移到-040) 处理旧 shared 位置与 study.yaml 私有设置。
3. 需要适配的是异常/显示边界：status/report 的不可用格为 `-`；compare 的坏输入、非有限/负容差和 --out 拒绝退出 2。修复坏文件或调用方参数，不通过把坏数据转空、删除 peer 或覆盖旧结果来绕过错误。
4. 源码更新会改变来源 hash。新实测沿用已有研究合同，使用新 version / fresh make 并重新过计划门；不重签旧 provenance，不将旧成功结果改署为 v0.4.1。现有不可变输入可继续共享，可变对象/checkpoint/sampler/RNG 仍每 Run 独立。
