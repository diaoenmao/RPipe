### 修复与证据

- [aad5d60](https://github.com/diaoenmao/RPipe/commit/aad5d60) 修正 dev 的 Factory 来源匹配、train 均值分段、topk 样本计数、零评测预算和曲线进度处理。这些是 dev 实现中的修复，不统称旧 main 的缺陷。
- [216e2b8](https://github.com/diaoenmao/RPipe/commit/216e2b8) 提交正式历史 Study、现代对照报告、实测图和复跑入口。历史报告记录 32 条四 seed 连续 80000-step 训练与 32 条自身 best 评测，八组固定 PNG 估读门通过；现代报告记录受控 60-step 对照。具体条件与失败结果保留在 [历史 Study](../../studies/main_historical/README.md) 和 [现代本机结果](../../studies/main_reproduction/docs/CURRENT_DEVICE_RESULT.md)。
- [392823b](https://github.com/diaoenmao/RPipe/commit/392823b) 保留实测源码在不同系统 checkout 时的原始换行字节。[f603324](https://github.com/diaoenmao/RPipe/commit/f603324) 记录发布准备 CI 的实测结果；[704f79f](https://github.com/diaoenmao/RPipe/commit/704f79f) 将两个 CI 工作流设为 `MPLBACKEND=Agg`，避免 Windows Tk / Tcl 环境故障。

### 验证与边界

此前 [`b95873f`](https://github.com/diaoenmao/RPipe/commit/b95873f) 的 [Unit Tests](https://github.com/diaoenmao/RPipe/actions/runs/37211900661) 与 [Package Check](https://github.com/diaoenmao/RPipe/actions/runs/37211900673) 已成功。v0.2.0 的版本号修订、安装包和最终提交继续由自己的 CI 验证，不以旧提交通过代替新提交通过。

实验报告是原实测源码的固定快照，本次版本号修订不重新运行 GPU 实验或改写报告 SHA。严格复核旧报告的全部 99 项源码字节时使用 `b95873f`；当前生产源码相对该提交仅改变 `__version__`。图像估读不等于恢复历史日志，也不证明全 80000-step 权重逐位一致。原生 checkpoint 恢复不承诺完整 RNG / sampler 与无中断训练逐位一致；外部 HF / GPU / slow 流程未纳入 CPU 发布门。

旧接口、配置与 checkpoint 迁移见 [MAIN_MIGRATION](../MAIN_MIGRATION.md)。长期分支保留 `main` 与 `dev`；[两个版本的完整差异](https://github.com/diaoenmao/RPipe/compare/v0.1.0...v0.2.0)以实际标签为准。

### Fixes and evidence

- [aad5d60](https://github.com/diaoenmao/RPipe/commit/aad5d60) fixes dev Factory source matching, interval train means, per-sample topk counting, zero evaluation budgets and curve progress handling. These are dev implementation fixes, not a blanket claim about defects in the original main.
- [216e2b8](https://github.com/diaoenmao/RPipe/commit/216e2b8) commits the historical Study, modern comparison reports, measured figures and rerun entry points. The historical reports record 32 four-seed continuous 80000-step training runs and 32 evaluations of each run's own best checkpoint, passing eight predefined PNG-estimation gates. The modern reports record controlled 60-step comparisons. Conditions and original failures remain in the [historical Study](../../studies/main_historical/README.md) and [modern device results](../../studies/main_reproduction/docs/CURRENT_DEVICE_RESULT.md).
- [392823b](https://github.com/diaoenmao/RPipe/commit/392823b) preserves measured source line-ending bytes across platform checkouts. [f603324](https://github.com/diaoenmao/RPipe/commit/f603324) records actual release-preparation CI results. [704f79f](https://github.com/diaoenmao/RPipe/commit/704f79f) sets `MPLBACKEND=Agg` in both CI workflows to avoid Windows Tk / Tcl failures.

### Validation and limits

The earlier [`b95873f`](https://github.com/diaoenmao/RPipe/commit/b95873f) passed [Unit Tests](https://github.com/diaoenmao/RPipe/actions/runs/37211900661) and [Package Check](https://github.com/diaoenmao/RPipe/actions/runs/37211900673). The v0.2.0 numbering correction, distributions and final commit must pass their own CI; earlier success is not treated as validation of a later commit.

Experiment reports remain fixed snapshots of the measured source. Renumbering does not rerun GPU experiments or rewrite report hashes. Use `b95873f` to audit all 99 original source hashes exactly; the current production source differs only in `__version__`. PNG estimation does not recover original logs or establish bitwise weight equality across all 80000 steps. Native checkpoint recovery does not guarantee complete RNG / sampler equivalence to uninterrupted training. External HF, GPU and slow workflows are outside the CPU release gate.

See [MAIN_MIGRATION](../MAIN_MIGRATION.md) for interface, configuration and checkpoint migration. The long-term branches are `main` and `dev`. The [full version comparison](https://github.com/diaoenmao/RPipe/compare/v0.1.0...v0.2.0) follows the actual tags.
