# 一、适用范围与核心规则

本规范用于单一课题的学术和技术文献调研，包括论文检索、论文阅读、文献分类、资料归档、论文索引、技术脉络梳理和文献调研报告写作。多个既有大类和 topic 的批量盘点、命名、查重与索引重建，使用 [《论文库全库整理规范 Paper Library Governance Standard》](./论文库全库整理规范%20Paper%20Library%20Governance%20Standard.md)。

适用对象包括论文、综述、教材、标准、技术报告、官方实现、Benchmark 和与研究问题直接相关的工程资料。软件产品调查、市场调查、竞品分析、采购选型和一般事实调查不使用本规范，应另行制定相应规范。

核心规则如下：

1. 每个课题在论文库中建立一个独立文件夹，统一命名为 `中文名 English Name`。
2. 调研正文、调研大纲与论文 PDF 分开管理；调研文档通过论文索引关联论文文件。
3. 论文按“研究问题或技术主题”分类，不按会议、年份或下载批次分类。
4. 单个课题内，同一版本只保存一份，跨主题关系优先写进索引。跨大类或不同 topic 是否保留副本，按《论文库全库整理规范》执行。
5. 文件名必须让人脱离索引也能大致识别论文。
6. `论文索引` 面向检索和阅读，`入库记录` 面向统计、校验和自动化。
7. PDF 文件名只包含发表年份、发表渠道和官方论文标题；渠道等级等可变信息记录在索引中。
8. `NR` 表示 `Not Ranked`，只用于已确认不参与渠道排名的来源；元数据证据不足使用状态 `Unverified`，不得用 `NR` 表示“未识别”。
9. 只有证据充分的论文才重命名。`Unverified` 条目保留原名和既有分类，不把推测写入文件名。
10. 新增、移动或重命名论文时，必须同步更新课题索引和入库记录，并校验本地引用。

# 二、目录分类规范

## （一）论文库总体结构

论文库采用“总入口—课题—主题分类—论文”的四层结构：

```text
论文库/
├─ 论文库说明与总索引
├─ Inbox 待归档/
├─ [课题中文名 English Name]/
│  ├─ 课题论文索引
│  ├─ Surveys and Tutorials/
│  ├─ Foundations and History/
│  ├─ [核心主题一]/
│  ├─ [核心主题二]/
│  └─ ...
├─ [另一课题中文名 English Name]/
└─ ...
```

结构规则：

- `论文库说明与总索引` 记录课题清单、课题入口、维护规则和跨课题检索入口，不存放论文副本。总索引至少包含 `课题、研究范围、课题入口、维护人、最后更新日期`。
- 根目录的课题文件夹不编号，避免新增课题导致整体重排；统一使用 `中文名 English Name` 命名。
- 每个课题内的 `课题论文索引` 记录分类说明、论文位置、阅读顺序和研究价值。
- `Inbox 待归档` 只用于尚未判断归属分类的临时文件。已经明确 topic、但年份或渠道证据不足的文件可留在正式分类并标记为 `Unverified`，不必仅因元数据不完整移入 Inbox。
- 调研大纲、正式报告和交接文档不混放在论文分类文件夹中，通过索引与论文库关联。

课题文件夹示例：

```text
量化 Quantization/
超分辨率 Super-Resolution/
计算机算术 Computer Arithmetic/
推理时训练 Test-Time Training/
```

## （二）课题内一级分类规则

课题内的主题分类默认不编号。各分类是并列的研究问题，不用文件夹名称表达阅读顺序、重要程度或发展阶段；这些关系统一写入课题论文索引。

可按需采用以下常见分类：

| **类别** | **内容** |
|---|---|
| Surveys and Tutorials | 综述、教程、教材和领域全景。 |
| Foundations and History | 奠基理论、历史起点和基础定义。 |
| Topic Categories | 按课题本身的主要技术主题建立的分类。 |
| Systems and Implementation | 系统、算子、工程实现和部署。 |
| Benchmarks and Evaluation | Benchmark、评测、复现与经验研究。 |
| Adjacent Topics | 有参考价值但不属于主线的相邻方向。 |

这只是分类参考，不要求每个课题把所有类别建齐。空目录不创建，分类名称也不需要为了排序添加数字或字母前缀。

## （三）怎样确定分类

分类名称应回答“这组论文共同研究什么问题”，例如：

```text
Arithmetic Algorithms and Datapaths
Floating Point Rounding and Reproducibility
Vector Matrix and AI Accelerators
Mixed Precision FP8 and Microscaling
Memory Hierarchy Data Movement and Interconnect
LLM Low Precision and Serving
```

不要混用不同分类轴：

- 不要同时出现“Transformer”“2025 Papers”“NeurIPS”“重要论文”这类不同性质的并列目录。
- 不按作者、会议、年份、是否已读或下载顺序作为主目录。
- `待读`、`已读`、`重点`属于阅读状态，应写进索引或 Zotero 标签，不单独复制 PDF。
- 一篇论文跨多个主题时，默认放入最能代表其主要贡献的目录，其他主题通过索引标签关联；不同大类或独立 topic 确有本地浏览需要时，可按“跨分类副本”规则分别保留。

## （四）什么时候增加子目录

出现以下情况之一时，可增加二级目录：

- 一个一级目录超过约 20—30 篇，浏览明显困难。
- 一级目录内部存在两个以上稳定、清晰的方法分支。
- 需要把算法论文与系统论文明确分开。

二级目录同样不编号，例如：

```text
LLM Low Precision and Serving/
├─ Quantization and Low Precision/
└─ Attention KV Cache and Serving/
```

一个课题内最多保持两级主题分类。更细的关系使用索引标签，不继续无限建文件夹。

## （五）跨课题论文的归属

一篇论文同时服务多个课题时，单课题调研默认使用“一个主文件 + 跨课题引用”：

1. 将主文件放入最能代表其主要贡献、且预计长期维护的课题与分类。
2. 在其他课题索引中增加该论文条目，直接链接主文件，并标记 `Cross-topic reference`。
3. 如果全库维护需要在不同大类或 topic 下分别保留副本，按《论文库全库整理规范》的跨分类副本规则执行。
4. 如果论文的主归属后来改变，移动主文件并同步更新所有索引链接。

# 三、论文 PDF 命名规范

## （一）标准格式

正式入库论文统一使用：

```text
[发表年份] - [发表渠道] - [官方论文标题].pdf
```

示例：

```text
2023 - ICML - SmoothQuant Accurate and Efficient Post-Training Quantization for Large Language Models.pdf
2024 - CVPR - Official Paper Title.pdf
2025 - arXiv - Official Preprint Title.pdf
2019 - Standard - Official Standard Title.pdf
```

各部分含义：

- **发表年份**：正式发表论文使用正式出版年份；只有预印本时使用首次公开年份；标准、白皮书和技术报告使用该版本的发布日期年份。
- **发表渠道**：使用稳定、通行的官方简称，如 `NeurIPS`、`ICML`、`ICLR`、`CVPR`、`ACL`、`JMLR`、`arXiv`、`Standard`、`Whitepaper`。
- **官方论文标题**：默认保留完整的官方英文标题；只有为满足路径长度兼容要求时，才按下述规则受控简写。

渠道等级使用 `T0`、`T1`、`T2`、`T3` 或 `NR`，但只记录在论文索引和发表渠道等级表中，不写进文件名。这样 Rank 调整时不需要批量重命名论文。

### 路径长度与受控简写

1. 路径长度按“盘符 + 全部目录 + 文件名 + `.pdf`”的完整绝对路径计算，不能只检查文件名。
2. 完整路径建议不超过 240 个字符；达到 240 个字符时应复核并优先缩短，正式入库路径硬性必须小于 260 个字符。
3. 缩短时先使用官方或学界通用的渠道简称，再删除渠道中的 `Proceedings of`、出版社名等冗余前缀；只有仍然过长时才压缩标题。
4. 渠道简称建议不超过 24 个字符，并与 `发表渠道等级表` 的 `Abbreviation` 完全一致。官方全称保留在等级表或索引元数据中，不必写入 PDF 文件名。
5. 标题简写必须保留方法名、系统名、模型名和足以区分论文的核心词；可以删除重复修饰语或非必要副标题，但不得截断单词、使用纯哈希名或改变标题含义。
6. 文件名采用短标题时，课题索引或入库记录仍须保存完整官方标题和来源，确保可追溯。

## （二）渠道等级 Rank 方案

渠道等级评价发表渠道，不直接评价单篇论文质量。论文价值由索引中的“价值类型和一句话价值”单独说明；阅读优先顺序根据具体课题和当前研究目标动态决定，不设置全局阅读优先级。

| **等级** | **定义** | **使用规则** |
|---|---|---|
| T0 | 领域公认的最高层级、对研究方向具有基础性影响的核心会议或期刊。 | 采用明确白名单。AI 核心会议初始设为 `NeurIPS`、`ICML`、`ICLR`。 |
| T1 | 对应研究领域内稳定处于前十、影响力和评审质量均较高的会议；期刊单独评价，不与会议混排。 | 必须进入该领域年度渠道表的 T1 白名单；已列入 T0 的渠道不重复计入。 |
| T2 | 领域内正规、稳定、具有良好同行评审的主流会议或期刊。 | 有持续举办或出版记录，但未进入 T0/T1。 |
| T3 | 新兴、小型、区域性、专题性渠道或 Workshop。 | 有正式评审，但影响力、稳定性或覆盖面有限。 |
| NR | 不参与渠道排名。 | arXiv 等预印本、标准、白皮书、书籍、学位论文、内部或公开技术报告。 |

建立并维护一份独立的 `发表渠道等级表 Venue Ranking`，作为所有课题共用的唯一等级依据，至少包含：

| **字段** | **说明** |
|---|---|
| Domain | 所属领域，如 AI、Computer Vision、NLP、Systems、Hardware。 |
| Venue | 官方名称。 |
| Abbreviation | 文件名使用的唯一简称。 |
| Type | Conference、Journal、Workshop 或其他类型。 |
| Rank | T0、T1、T2、T3、NR。 |
| Basis | 排名依据和必要说明。 |
| Sources | 使用的数据来源与查询日期。 |
| Score | 年度综合评分；T0 和 NR 可不填写。 |
| EffectiveYear | 本等级开始采用的年份。 |
| LastReviewed | 最近复核日期。 |

Rank 建设按以下计划执行：

1. 先建立 AI 领域初始表，将 `NeurIPS`、`ICML`、`ICLR` 列为 T0。
2. 再按 Computer Vision、NLP、Data Mining、Robotics、Systems、Hardware 等子领域分别收集候选渠道，不做跨领域的单一总榜；会议和期刊分别排序。
3. 对候选会议建立年度证据表，建议评分维度为：领域公认名单与学术共同体认可度 35%、近 3—5 年论文影响 25%、评审质量与选择性 20%、连续举办与长期稳定性 10%、与本领域研究范围的匹配度 10%。所有数据必须记录来源和查询日期。
4. 排除数据缺失、停办、定位明显改变或主要属于其他领域的渠道后，按综合评分排序。每个子领域的 T1 会议最多十个；并列边界由人工复核决定，不能仅依据某一年的引用指标或录取率。
5. 期刊使用相同证据维度建立独立榜单，不占用会议的十个 T1 名额；跨领域综合期刊必须注明适用范围。
6. 同一渠道跨多个领域时只保留一个标准简称；Rank 不一致时，在等级表中明确主领域和适用说明。
7. 新渠道或证据不足时 Rank 留空，论文状态标记为 `Unverified`。分类已经明确时可留在正式 topic；分类也不明确时才进入 Inbox。不得自行猜测 Rank，也不得用 `NR` 代替未确认状态。
8. 每年固定一个数据截止日，生成带年份的渠道表版本，并由论文库维护人和至少一名对应领域研究者复核。变更必须记录依据和原因。
9. Rank 调整后只更新发表渠道等级表和论文索引，不重命名 PDF。
10. Rank 只表示渠道层级，不代表论文质量、研究价值或阅读顺序。高价值预印本可能比与当前课题无关的 T0 论文更值得优先阅读。

## （三）标题与渠道写法

1. 先从正式出版页面或 arXiv 页面核对年份、渠道和官方标题，不直接采用浏览器下载名或 PDF 内部元数据。
2. 正式发表后使用正式渠道，不再写 `arXiv`；只有尚未正式发表的预印本才在文件名中使用 `arXiv`，并在索引中记录为 `NR`。
3. 标题默认保留官方英文；原文标题不是英文时，优先使用出版页面提供的官方英文译名，没有官方英文译名时保留原文标题。
4. 方法名、系统名或模型名只在它属于官方标题时出现，不额外添加作者名、DOI、arXiv ID 或自拟简称。
5. 使用半角连接符和空格 ` - ` 分隔年份、渠道和标题。渠道简称的大小写必须与 `发表渠道等级表` 一致。
6. 同一标题发生冲突时，在标题后增加必要的版本标识或 arXiv ID，不改变前面的年份与渠道格式。
7. 若完整路径达到 240 个字符，按“渠道简称 → 删除冗余渠道前缀 → 受控压缩标题”的顺序处理；达到或超过 260 个字符的文件不得正式入库。
8. 受控简写只改变文件名展示，不改变索引中保存的官方标题、官方渠道名称和来源证据。

同名冲突示例：

```text
2025 - arXiv - Official Paper Title - arXiv 2501.12345.pdf
2025 - arXiv - Official Paper Title - arXiv 2502.67890.pdf
```

## （四）补充材料与非论文文件

```text
[年份] - [发表渠道] - [官方论文标题] - Supplement.pdf
[年份] - [发表渠道] - [官方论文标题] - Code and Data Supplement.zip
[年份] - Technical Report - [正式标题].pdf
[年份] - Standard - [标准名] - Version [版本号].pdf
```

主论文与补充材料使用相同的标题前缀，确保排序后相邻。

## （五）版本与重复文件

同一论文出现多个来源或版本时，按以下规则处理：

1. arXiv 版与正式出版版内容基本一致时，只保留正式出版版；正式版不可取得或 arXiv 版明显更新时，保留信息更完整的版本，并在索引中记录版本与来源。
2. 同一论文的修订版原则上替换旧版，不同时保留多个 PDF；索引保留版本变更说明。
3. 正式版与预印本存在实质差异、且研究确实需要比较时，可以同时保留，并在文件名末尾使用 ` - Published Version`、` - arXiv vN` 等后缀消歧。
4. 会议论文与显著扩展的期刊论文视为两篇独立文献，分别按各自官方标题命名，并在索引中说明继承关系。
5. 入库前先查标题、DOI/arXiv ID、作者和文件哈希；不得仅因文件名不同就认定为不同论文。

## （六）禁止使用的文件名

禁止保留以下下载器或网站生成的名称：

```text
paper.pdf
main.pdf
download.pdf
2401.12345.pdf
document(1).pdf
submission_8346.pdf
一串哈希值.pdf
```

为保证预览、下载和跨系统同步兼容，文件名不使用 `< > : " / \\ | ? *`。冒号通常替换为 ` - `，其余标点尽量使用普通半角字符。禁止保留使完整绝对路径达到或超过 260 个字符的文件名，也不得用截断单词、纯哈希或无语义编号的方式机械缩短。

# 四、论文索引规范

## （一）索引的作用

每个课题的 `课题论文索引` 负责四件事：

1. 说明论文库怎样分类。
2. 统计每类论文数量。
3. 给出建议阅读顺序。
4. 记录每篇论文的基本信息、渠道等级、价值类型、一句话价值和阅读状态。

PDF 文件名记录年份和发表渠道；论文索引将年份、渠道和 Rank 拆成独立字段，便于筛选、统计和更新。需要观察技术演进时，可在分类内部按年份排序。

## （二）索引结构

索引可以使用文档表格、电子表格或数据库维护。无论使用哪种载体，都应保留以下逻辑结构：

```markdown
# 一、馆藏概览

| **分类** | **数量** | **核心问题** |
|---|---:|---|
| Surveys and Tutorials | 6 | 领域知识地图与基础教程 |
| Foundations and History | 8 | 奠基理论与历史起点 |

# 二、建议阅读顺序

## （一）先建立整体认识
1. [综述论文文件名](论文文件引用)
2. [奠基论文文件名](论文文件引用)

简要说明为什么这样安排。

# 三、分类论文索引

## Surveys and Tutorials

| **论文** | **年份** | **Rank/渠道** | **状态** | **价值类型** | **一句话价值** | **标签** | **阅读状态** |
|---|---:|---|---|---|---|---|---|
| [2024 - Venue - A Survey of ...pdf](论文文件引用) | 2024 | T1 / Venue | Published | 全景综述 | 建立领域分类与方法地图 | survey, PTQ, QAT | 已读 |

# 四、校验结果

| **检查项** | **结果** |
|---|---:|
| PDF 总数 | 75 |
| 无效 PDF | 0 |
| 重复文件 | 0 |
| 待归档文件 | 0 |
| 失效论文引用 | 0 |
```

## （三）单篇论文最低字段

每篇论文至少记录：

- 规范文件名和论文文件引用。
- 发表年份、渠道等级和发表渠道。
- 发表状态：`Published`、`Accepted`、`Preprint`、`Standard`、`Whitepaper`；元数据证据不足时另将入库 Status 标记为 `Unverified`。
- 一句话作用：为什么收录，它在技术脉络中的位置是什么。
- 价值类型：论文提供哪一种研究价值。
- 标签：跨主题关系、对象、方法或系统位置。
- 阅读状态：`待读`、`略读`、`精读`、`已总结`。

精读论文再补充以下字段：

- 机构：优先记录主要研究机构，不必在总表中展开全部作者。
- 发表场所：会议、期刊或预印本平台。
- 论文类型：`Survey`、`Theory`、`Method`、`Application`、`System`、`Benchmark`。
- 目标：论文解决什么问题。
- 方法：使用什么算法、模型或理论。
- 创新点：相比先前工作新增了什么。
- 数据集、评估指标和主要结果。
- 论文链接、代码链接和 BibTeX。
- 与当前研究的关系、关键问题或后续想法。

论文较多时，不要把所有详细字段硬塞进一张 Markdown 宽表。采用两层索引：

1. `课题论文索引` 保存分类概览、阅读顺序和简洁条目。
2. 电子表格或数据库形式的 `课题文献表` 保存机构、场所、目标、方法、创新、数据集、指标、结果、论文引用和代码等详细字段。

## （四）论文价值标注

论文价值标注由“价值类型 + 一句话价值”组成。引用次数和 Venue Rank 只作为参考，不直接决定论文对当前研究的价值。

**价值类型**

| **标注** | **适用论文** |
|---|---|
| 全景综述 | 建立领域范围、术语和分类体系的综述或教程。 |
| 奠基理论 | 定义问题、提出基础理论或形成长期使用框架的论文。 |
| 关键方法 | 开创主要技术路线或显著改变方法设计的论文。 |
| 系统实现 | 将算法落实到算子、框架、硬件或端到端系统的论文。 |
| Benchmark | 建立数据集、指标、基线或统一评价协议的论文。 |
| 复现评测 | 系统比较、复现、审计或揭示方法实际表现的论文。 |
| 反例边界 | 揭示失败条件、理论下界、负结果或适用范围的论文。 |
| 前沿进展 | 时间较新、可能形成新分支，但证据仍在积累的论文。 |
| 研究相关 | 能直接支持当前研究假设、方法实现或实验设计的论文。 |

同一篇论文可以有多个价值类型，主价值写在前面，例如 `关键方法 / 系统实现`。

“一句话价值”应说明这篇论文为什么进入资料库，例如：

- 首次把量化误差与 diffusion 采样方程直接连接。
- 建立 KV Cache 量化的强基线，并提供真实长上下文实验。
- 给出 Re-Pair 最坏情况近似下界，限定贪心方法的理论能力。
- 提供当前研究系统所需的关键实现依据。

## （五）索引写作规则

- “作用”写论文的独特位置，不复制摘要。
- 每篇正式收录的论文都应填写“一句话价值”；无法说明收录价值时，应重新判断是否需要入库。
- 阅读顺序以当前课题的知识依赖和研究需求为准，不由 Venue Rank 机械决定，也不作为论文的固定属性写入索引。
- 同一标签使用固定拼写，不同时出现 `KV cache`、`KV Cache`、`kvcache`。
- 建议阅读顺序按知识依赖组织，不按年份机械排序。
- 分类内部的完整文献表默认按发表日期排序，以便观察技术演进。“建议阅读顺序”仍按知识依赖组织。
- 新论文先进入对应分类，再决定是否加入“建议阅读顺序”。
- 删除或移动 PDF 后，索引中不能保留失效链接或错误的逻辑位置。

# 五、入库记录与查重规范

`入库记录` 用于统计、查重和质量检查，不代替课题论文索引。推荐字段：

字段说明：

| **字段** | **内容** |
|---|---|
| Topic | 归属课题。 |
| Category | 课题内的主要分类。 |
| File | 最终规范文件名。 |
| Year | 发表年份。 |
| Rank | 渠道等级。 |
| Venue | 发表渠道的标准简称。 |
| Reference | 论文文件引用。 |
| Status | `Valid`、`Unverified`、`Duplicate`、`Missing`、`Invalid`。 |
| Bytes | 文件字节数。 |
| Source | PDF 或官方落地页链接。 |
| AddedAt | 入库日期，格式 `YYYY-MM-DD`。 |
| SHA256 | 文件哈希，用于去重和完整性检查。 |

核心必填字段为 `Topic、Category、File、Reference、Status、AddedAt`。Status 为 `Valid` 时，`Year、Rank、Venue、Source` 必填；Status 为 `Unverified` 时允许暂空，且 Rank 不得用 `NR` 代替未知。SHA-256 能稳定取得时应填写；不能取得时，至少通过官方标题、作者、DOI/arXiv ID 和文件大小联合查重。

# 六、文献检索与论文阅读

这一部分只规定与分类和索引直接相关的最小流程。

## （一）先用综述建立分类

1. 从较宽的中英文关键词开始搜索，再增加方法名、任务名、模型名或系统名缩小范围。
2. 优先找较新的高质量综述，用它建立关键词表、初始分类和代表论文清单。
3. 从综述和奠基论文的参考文献向过去追溯，再通过“被引用”查找后续工作。
4. 进入新分支后继续使用“分支关键词 + survey/benchmark/system”等组合搜索。
5. Awesome 列表、排行榜和社区书单只作为入口，最终条目回到原论文或官方页面核对。

## （二）论文筛选口径

按论文类型使用不同侧重点：

| **类型** | **筛选重点** |
|---|---|
| 综述/教程 | 优先较新、覆盖完整且分类清晰的工作，再参考引用和发表场所。 |
| 奠基/创新论文 | 优先方法原创性和历史影响，再参考引用、发表场所和年份。 |
| 最新进展 | 日期和与课题的直接相关性更重要，不能因引用少就排除。 |
| 工程/系统论文 | 除论文质量外，重点检查代码、硬件条件、复现性和端到端结果。 |

引用次数和发表场所是筛选线索，不是质量结论。新论文天然引用较少，不同领域的会议与期刊地位也不同。

## （三）三档阅读深度

| **阅读方式** | **操作** | **索引状态** |
|---|---|---|
| 快速浏览 | 读标题、摘要、结论，浏览章节、图表和方法总览图。判断是否相关及放入哪个分类。 | `略读` |
| 针对性阅读 | 读引言、相关工作、问题定义、核心方法和关键实验。填写目标、方法、创新和主要结果。 | `精读中` |
| 深入阅读 | 通读正文与附录，检查公式、实验设置、基线、消融和代码。用自己的话总结并记录疑问。 | `精读` 或 `已总结` |

不是每篇收录论文都需要精读。先快速浏览和归类，只对奠基论文、核心路线、关键对照和当前研究直接相关的论文深入阅读。

## （四）精读记录模板

```markdown
### [方法名 / 论文简称]

- 论文：[规范文件名](论文文件引用)
- 类型：Survey / Theory / Method / Application / System / Benchmark
- 目标：解决什么问题？
- 方法：核心算法、模型或理论是什么？
- 创新：相比最接近的工作新增了什么？
- 实验：数据集、指标、基线、消融和主要结果。
- 位置：属于哪个分类？与哪些工作相同或不同？
- 关系：对当前研究有什么可用之处？
- 问题：哪些主张证据不足？产生了什么新问题或想法？
- 引用：论文链接、代码链接、BibTeX、关键页码/图表。
```

# 七、新论文入库流程

每新增一篇论文，只做以下八步：

1. 核对标题、作者、年份、发表状态、DOI/arXiv 和官方下载来源。
2. 快速浏览标题、摘要、结论、图表和章节，判断是否值得收录。
3. 判断它主要回答哪个研究问题，选择主课题和主要分类。
4. 按命名规范重命名 PDF，并在最终分类位置计算完整绝对路径；达到 240 个字符时受控简写，达到或超过 260 个字符时不得入库。
5. 使用常规 PDF 阅读工具检查文件能否打开、是否为真正 PDF、是否缺页，并确认改名后的路径可访问。
6. 计算 SHA-256，或通过标题、作者、DOI/arXiv ID 和文件大小与已有文件查重。
7. 将文件放入论文库的正式分类，并在 `入库记录` 中增加一行；跨大类副本按全库整理规范记录。
8. 在课题论文索引中增加论文条目。精读内容进入课题文献表，只有真正关键的论文才加入建议阅读顺序。

涉及多个既有大类或多个 topic 的批量整理，不使用本节的简化流程，改用《论文库全库整理规范 Paper Library Governance Standard》。

# 八、文献调研大纲与正式报告规范

## （一）两个文件的职责

`[课题中文名] 文献调研 Literature Search 大纲` 是研究设计文件，负责确定问题、边界、章节、分类轴、代表论文和尚未确认的内容。

`[课题中文名] 文献调研 Literature Search` 是正式报告，负责给出结论、机制解释、论文证据、比较结果、适用边界和下一步判断。

两份文件应保持主要章节对应。检索过程中发现原分类不成立时，可以调整大纲，再同步修改正式报告结构。

## （二）大纲的标准结构

大型课题的大纲优先采用以下结构，并按课题需要删减：

```text
一、执行摘要
    研究问题
    核心判断
    全文分析轴

二、范围、术语与统一问题表述
    纳入与排除范围
    易混概念
    基本对象、公式或系统边界

三、时间主线
    按关键矛盾或范式转变分期

四、方法类型主线
    按稳定的方法分类展开

五、其他必要分析轴
    对象、模型、算法过程、系统、应用或证据

六、评估与比较
    指标、数据集、基线、成本和最小实验矩阵

七、综合判断与开放问题
    共识、争议、研究机会和下一步

八、参考文献与公开实现
    检索范围、分类书目、论文库和代码
```

每个大纲章节不能只写标题，还应简要说明：

- 本章回答什么问题。
- 使用哪一种分类标准。
- 纳入哪些代表论文或系统。
- 需要哪些公式、比较表或实验矩阵。
- 哪些内容在其他章节讨论，避免重复。

## （三）时间线怎么写

时间线用于解释研究矛盾如何变化，不用于逐年罗列论文。分期边界应对应技术范式、研究对象、关键基础设施或评价目标的变化。

每个时期至少说明四项内容：

1. 当时主要解决什么问题。
2. 出现了哪些代表论文、系统或标准。
3. 相比上一时期新增了什么能力。
4. 哪些限制推动了下一阶段。

现有资料中的分期方式包括：

- 量化按离散神经计算、有限精度网络、可训练离散化、整数部署、大模型 PTQ 和生成模型量化演进。
- 超分辨率按成像反演、学习型映射、CNN、GAN、Transformer 和 diffusion/video foundation model 演进。
- Test-Time Training 按局部学习、经典 TTT、持续 TTA、语言模型、测试期 RL 和单问题发现演进。
- 计算机算术按机械算术、现代算术算法、VLSI、IEEE 754、GPU、Tensor Core 和块格式演进。

时间段不要求等长。一个真正改变问题定义的年份可以独立成段，长期连续演进也可以合并为一个阶段。

## （四）方法类型怎么分

方法分类应选择一个稳定的主轴，回答“这些方法通过什么机制解决问题”。其他维度分别建立独立章节，不放在同一级目录混排。

常用分析轴如下：

| **分析轴** | **回答的问题** | **示例** |
|---|---|---|
| 对象 | 方法处理什么数据、状态或组件 | 参数、瞬时 Activation、KV Cache、生成 Latent |
| 模型结构 | 问题发生在哪类内部结构 | CNN、Transformer、U-Net、DiT |
| 外部算法过程 | 模型怎样被调用，误差怎样反馈 | 单次前向、自回归、Diffusion、Flow、在线更新 |
| 方法机制 | 方法通过什么机制改变结果 | Scaling、Rotation、重构、对齐、传播、蒸馏、RL |
| 状态与生命周期 | 更新或缓存保留多久 | 单实例、Session、持续流、全局状态 |
| 系统实现 | 方法怎样转化为真实执行 | 数据格式、Kernel、运行时、服务与硬件 |
| 评估证据 | 结论由什么层级的证据支持 | 理论、论文实验、公开代码、复现、端到端部署 |

不同课题应选择与问题匹配的分类方式：

- 量化可拆成量化对象、模型结构、外部生成算法、量化方法和低比特系统。
- 超分辨率可拆成信息来源、对齐传播、放大位置、生成先验、损失和评估。
- Test-Time Training 可拆成训练数据来源、优化目标、更新对象和状态寿命。
- 计算机算术可拆成数值表示、误差与舍入、算术算法、数据通路、体系结构和存储系统。

## （五）正式报告怎么展开

正式报告沿用大纲的主结构。每个方法家族或专题按以下顺序展开：

1. **共同问题**：这一类方法解决什么矛盾。
2. **核心机制**：共同公式、流程、数据路径或设计假设是什么。
3. **代表论文**：选择奠基工作、关键方法、强基线和重要转折论文说明路线形成与发展。
4. **方法差异**：各代表工作真正新增了什么，不能只改写摘要。
5. **证据与代价**：使用什么数据集、指标、硬件、基线和实现验证，付出什么成本。
6. **适用边界**：在哪些任务、模型、条件或系统上不能直接推广。
7. **当前判断**：该路线在整个课题中的位置，以及是否值得继续研究或采用。

同一组论文应围绕共同问题合并讨论。单篇论文只有在以下情况才单独成节：

- 它定义了新的问题或基础理论。
- 它开创了独立且重要的方法分支。
- 它是当前研究必须深入理解的关键方法或系统。
- 它需要专门核验争议、传闻或异常证据。

## （六）执行摘要和结论

执行摘要应在正文完成后回写，至少包含：

- 调研范围与信息截止日期。
- 需要回答的核心问题。
- 主要分类轴。
- 3—7 条核心判断。
- 与当前研究最直接的关系。

综合结论负责收束全文，包含：

- 已形成共识的结论。
- 仍有争议或证据不足的问题。
- 最值得关注的方法路线。
- 建议的阅读、实验、复现或工程验证顺序。

## （七）正式报告的基本要求

- 标明信息截止日期。
- 优先引用原论文、官方页面和官方仓库。
- 按时间线和方法类型组织，不逐篇堆叠摘要。
- 论文声称、公开实现、复现结果和实际系统效果分别表述。
- 关键比较说明模型、数据集、指标、基线、硬件和版本。
- 报告中的代表论文应能在课题论文索引中找到对应条目、论文引用和价值标注。
- 大型课题先完成独立大纲。范围较小的单一问题可以直接形成正式报告。

# 九、推荐工具

| **用途** | **工具** | **建议** |
|---|---|---|
| 学术搜索 | [Google Scholar](https://scholar.google.com/) | 从宽关键词开始，使用年份、作者和出版物筛选，并沿“引用/被引用”追踪前后工作。 |
| 预印本与开放版本 | [arXiv](https://arxiv.org/) | 查找开放 PDF 和最新版本。arXiv 本身不做同行评审，正式发表状态仍需另行核对。 |
| 收集与管理 | [Zotero](https://www.zotero.org/) | 适合抓取论文元数据、管理 Collection/Tag、查找 PDF 元数据和阅读标注。 |
| DOI 元数据 | [Crossref REST API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/) | 用 DOI 或标题核对正式标题、作者、出版状态、期刊和年份。 |
| PDF 文本 | PDF 阅读器、文本抽取或 OCR 工具 | 抽取正文、检查页数与基本元数据。扫描 PDF 再使用 OCR。 |
| 文件校验 | SHA-256 工具 | 发现重复入库或同文件改名。 |
| 表格维护 | 电子表格 / 数据库 | 筛选入库状态、分类、Rank、渠道、标签和缺失字段。 |

工具用于提高整理效率，最终分类和“论文为何重要”仍需人工判断。Zotero 的 Collection 可以让同一条目出现在多个集合中，适合表达跨主题关系；文件副本是否跨大类或 topic 保留，按《论文库全库整理规范》执行。

Benchmark 优先查原论文、官方仓库和具体任务主页。

# 十、最简任务指令

以后可以直接这样要求：
